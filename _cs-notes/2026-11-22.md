# How websites store passwords

A good website never stores your password. It stores a hash of it.

- A hash function is like a blender: easy to run forward, practically impossible to un-blend.
- At login, the site hashes what you typed and compares it to the stored hash.
- A salt is a random string added before hashing, so two users with the same password get different hashes.
- Attackers can't reverse hashes, so they guess common passwords and hash each guess. Slow hashes (bcrypt, argon2) make that guessing expensive.
